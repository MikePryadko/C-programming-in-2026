# Память и владение

## Владение

### У каждой аллокации один владелец

Освободить блок может только тот, кто знает, что он больше никому не нужен, поэтому у каждого блока ровно один владелец: переменная либо владеет памятью, либо только заимствует её. Передачу владения записывают в контракте у каждого параметра и результата ([контракты API](06-api-and-modules.md)); имя функции подсказывает схему ещё до чтения комментария.

Соглашение об именах, которого придерживаются в примерах книги:

- `get`, `peek`: возвращают заимствованный указатель, владение не передаётся; `peek` подчёркивает, что указатель живёт только до следующей мутации объекта.
- `dup`: возвращает копию, владение копией у вызывающего.
- `take` (он же `steal`): отдаёт собственный указатель объекта вызывающему, а в объекте оставляет `nullptr`; освобождать будет вызывающий.
- `set`: заимствует аргумент и сохраняет собственную копию.

Квалификатор `const` в типе указателя читается как «не владею»: параметр `const char *` и результат `const char *` заимствованы, их не освобождают. Контейнер владеет всеми элементами или ни одним, смешанная политика в одном контейнере не допускается: при владеющей политике добавление передаёт владение (или копирует), а литерал и чужую строку кладут копией.

```c
#include <errno.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

typedef struct { char *path; } cfg; /* path принадлежит cfg */

/* cfg_set_path: p заимствуется, сохраняется копия. 0 или -ENOMEM; при ошибке без изменений */
static int cfg_set_path(cfg *c, const char *p) {
    char *copy = strdup(p);
    if (!copy) return -ENOMEM;
    free(c->path);
    c->path = copy;
    return 0;
}

/* peek: заимствованный указатель, действителен до следующего set/take */
static const char *cfg_peek_path(const cfg *c) { return c->path; }

/* take: владение переходит вызывающему (free), поле обнуляется */
static char *cfg_take_path(cfg *c) {
    char *p = c->path;
    c->path = nullptr;
    return p;
}

int main(void) {
    cfg c = {};
    if (cfg_set_path(&c, "/etc/app.conf") != 0) abort();
    printf("%s\n", cfg_peek_path(&c)); /* вывод: /etc/app.conf */
    free(cfg_take_path(&c));
    printf("%d\n", cfg_peek_path(&c) == nullptr); /* вывод: 1 */
    return 0;
}
```

В `cfg_set_path` копия создаётся до освобождения старого значения: при отказе `malloc` объект остаётся прежним.

#### Подводные камни

- Результат `peek` сохранён в долгоживущей структуре. После следующего `set`, `clear` или роста контейнера указатель висит; храни копию (`dup`) или индекс.
- После `take` и передачи владения указатель источника остаётся в локальной копии и выглядит живым. Обнуляй его сразу, как это делает `take`.
- Приведение `(char *)` с целью освободить заимствованный `const char *`. Если функция не обещала передачу владения, блок принадлежит другому коду: получишь двойное освобождение или освобождение статической строки.
- Владение не записано. Вызывающий и вызываемый предполагают разное: утечка либо обращение к освобождённой памяти; при неясной схеме прочитай код и допиши контракт, а не угадывай.

### Выделяй память без ловушек

Почти все ошибки с выделением памяти сводятся к четырём: неверный размер, переполнение при умножении, потеря старого указателя при `realloc` и неверное прочтение `nullptr` для нулевого размера. Размер берут от выражения, а не от типа: `sizeof *p` остаётся верным при смене типа указателя. Для массива используют `calloc(n, sizeof *p)` (обнулённая память, переполнение умножения проверяет сама) или проверку через `ckd_mul` из `<stdckdint.h>` ([целые типы и переполнение](02-types-and-ub.md)). Функция `reallocarray` выполняет ту же проверку для изменения размера, но это расширение POSIX и glibc (под `-std=c23` нужен `#define _GNU_SOURCE`).

```c
#include <errno.h>
#include <stdckdint.h>
#include <stdio.h>
#include <stdlib.h>

typedef struct { int *ptr; size_t len, cap; } ivec; /* как в главе о контейнерах */

/* ivec_push: 0 или -ENOMEM; при ошибке вектор не изменён */
static int ivec_push(ivec *v, int x) {
    if (v->len == v->cap) {
        size_t ncap = 4, bytes;
        if ((v->cap && ckd_mul(&ncap, v->cap, (size_t)2)) || ckd_mul(&bytes, ncap, sizeof *v->ptr))
            return -ENOMEM;
        int *np = realloc(v->ptr, bytes); /* результат отдельно: v->ptr пока нужен */
        if (!np) return -ENOMEM;
        v->ptr = np;
        v->cap = ncap;
    }
    v->ptr[v->len++] = x;
    return 0;
}

int main(void) {
    ivec v = {};
    for (int i = 0; i < 100; i++)
        if (ivec_push(&v, i) != 0) abort();
    printf("%zu %zu\n", v.len, v.cap); /* вывод: 100 128 */
    free(v.ptr);
    return 0;
}
```

Полный контейнер с `init`, `clear` и удалением: [контейнеры и обобщённый код](09-containers-and-generics.md).

Типичная ошибка выглядит безобидно:

```c
/* Ошибка: старый указатель затирается результатом realloc, умножение без проверки */
#include <stdlib.h>

int *grow(int *p, size_t n) { return p = realloc(p, n * sizeof(int)); }
```

При `nullptr` исходный блок остаётся выделенным, а указатель на него потерян (утечка); при большом `n` умножение переполняется, и `realloc` выделяет меньше нужного.

#### Подводные камни

- Нулевой размер. `malloc(0)` и `calloc(0, n)` вправе вернуть `nullptr` без нехватки памяти, а вправе уникальный указатель, который нужно освободить. Правило «`nullptr` значит нехватка памяти» ломается: обрабатывай `n == 0` отдельно до вызова.
- `realloc(p, 0)`. В C23 при `p != nullptr` поведение неопределено; компилятор молчит. В glibc вызов освобождает блок и возвращает `nullptr`, а в других реализациях может вернуть живой указатель, и тогда `p = realloc(p, 0)` даёт утечку или двойное `free`. Уменьшение до нуля пиши как `free(p)`.
- Рост блока перемещает его: указатели на элементы становятся висячими; храни индексы.
- `malloc` не обнуляет память. Чтение неинициализированных байт и утечка содержимого кучи через дополнение (padding) при записи структуры в файл или сокет ([системный уровень](11-system-io.md)); для структур с владеющими указателями бери `calloc` или init-функцию, иначе первая же очистка освободит мусор.
- `sizeof(p)` вместо `sizeof *p` для указателя. Выделяется размер указателя, а не объекта.

### Делай нулевое состояние допустимым

Если объект, заполненный нулями, уже корректен и безопасен для освобождения, то пропущенная или недоделанная инициализация превращается из неопределённого поведения в безобидное пустое состояние. Поэтому инициализируй всё: локальные структуры через `= {}`, динамические через `calloc`, а указатели, которыми владеет объект, держи в `nullptr`, пока блок не выделен. Функция очистки тогда безусловна: `free(nullptr)` допустим, проверок `if (p)` не требуется, а после освобождения указатель обнуляют, чтобы повторная очистка была безвредной.

Обнуление после освобождения удобно держать в макросе `#define FREE(p) do { free(p); (p) = nullptr; } while (0)`: он вычисляет аргумент несколько раз, поэтому ему передают только простое lvalue (поле, переменную), но не вызов функции. Откат частично созданного объекта на этом же приёме показан в следующей практике.

#### Подводные камни

- `char *p;` без инициализатора и ветка очистки с `free(p)` на раннем выходе. Освобождение мусорного указателя; ставь `= nullptr` при объявлении, а не при первом присваивании.
- Обнуление не стирает остальные копии указателя. После `FREE(c->host)` копия `h = c->host`, сделанная раньше, по-прежнему висит.

### Для каждого типа задай пару создания и уничтожения

Две пары функций покрывают все случаи, и их роли не смешивают: `create`/`destroy` для объекта, живущего в куче и имеющего собственную идентичность, `init`/`clear` для структуры, размещённой где угодно (на стеке, в поле другого объекта, в элементе массива). `init` приводит структуру из любого состояния в рабочее, `clear` освобождает внутренние ресурсы и возвращает её в нулевое состояние; сам блок структуры `clear` не освобождает. `create` равно `calloc` плюс `init`, `destroy` равно `clear` плюс `free`, причём `destroy(nullptr)` допустим, как и `free(nullptr)`.

```c
#include <errno.h>
#include <stdio.h>
#include <stdlib.h>

typedef struct { char *data; size_t len, cap; } buf;
typedef struct { buf in, out; } session;

static int buf_init(buf *b, size_t cap) {
    *b = (buf){};
    if (cap && !(b->data = malloc(cap))) return -ENOMEM;
    b->cap = cap;
    return 0;
}

static void buf_clear(buf *b) {
    free(b->data);
    *b = (buf){};
}

static void session_destroy(session *s) {
    if (!s) return;
    buf_clear(&s->in);
    buf_clear(&s->out);
    free(s);
}

/* Возврат: объект или nullptr; код результата (0 при успехе) кладётся в *err, если err не nullptr */
static session *session_create(int *err) {
    int rc = -ENOMEM;
    session *s = calloc(1, sizeof *s);
    if (s && (rc = buf_init(&s->in, 64)) == 0) rc = buf_init(&s->out, 64);
    if (rc != 0) { session_destroy(s); s = nullptr; }
    if (err) *err = rc;
    return s;
}

int main(void) {
    int err;
    session *s = session_create(&err);
    if (!s) return 1;
    printf("%zu %zu\n", s->in.cap, s->out.cap); /* вывод: 64 64 */
    session_destroy(s);
    return 0;
}
```

Нулевое состояние делает частичный отказ в `session_create` безопасным, без отдельного кода отката: недостроенный объект уничтожает тот же `session_destroy` ([ошибки и очистка](04-errors-and-cleanup.md)).

#### Подводные камни

- `init` на уже живом объекте. Старые указатели затираются, блоки теряются; перед повторным использованием вызывай `clear`.
- Копия структуры присваиванием: `a = b` для объекта с владеющими полями даёт двух владельцев одного блока и двойное освобождение. Либо запрети копирование (передавай указатель), либо пиши явную функцию глубокого копирования.
- `clear`, не возвращающая объект в нулевое состояние. Повторный вызов освобождает освобождённое; `clear` должна быть идемпотентной.
- `destroy` для объекта со стека или из массива освобождает чужой блок; для встроенных объектов вызывай `clear`.

### Выбери одну политику нехватки памяти для всей программы

Нехватка памяти обрабатывается либо везде одинаково, либо нигде не протестирована: проверки «на всякий случай» в реальном отказе дают непредсказуемый путь. Политику выбирают один раз, а выделение идёт только через её обёртки.

Завершение процесса через `abort` подходит серверам с перезапуском и утилитам: результат не проверяют. Возврат ошибки (`nullptr` или `-ENOMEM`) нужен библиотекам и демонам, где отказ одного запроса не должен убивать процесс: проверяют каждый вызов и откатывают состояние. Арена с фатальной нехваткой подходит запросу или фазе: результат не проверяют, а размер блока берут по худшему случаю (см. раздел про арены).

```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

/* Политика программы: нехватка памяти фатальна; всё выделение идёт через mem_*. */
static void *mem_alloc(size_t n, size_t size) {
    /* нулевой размер превращён в один элемент: nullptr здесь всегда нехватка */
    void *p = calloc(n ? n : 1, size ? size : 1);
    if (!p) {
        fputs("fatal: out of memory\n", stderr);
        abort();
    }
    return p;
}

void *mem_dup(const void *src, size_t n) { return memcpy(mem_alloc(n, 1), src, n); }
```

Библиотеки ведут себя по-разному: одни не проверяют результат `realloc`, другие завершают процесс (`g_malloc` в GLib), третьи возвращают код ошибки. Перед подключением выясни политику: завершающая процесс библиотека ломает программу с политикой «возврат ошибки».

#### Подводные камни

- Смешанная политика. Часть вызовов проверена, часть нет; проверенные ветки не исполнялись ни разу, и в первом настоящем отказе ломаются. Путь отказа проверяют инжекцией ([тесты и отладка](07-testing-and-debugging.md)).
- Библиотечный код с `abort` внутри. Вызывающий не может ни откатить состояние, ни сообщить пользователю; библиотеке отдают политику «возврат ошибки» ([контракты API](06-api-and-modules.md)).
- Ожидание «`nullptr` почти не бывает». Отказ реален при `ulimit -v`, огромных размерах и нехватке адресного пространства; код, считающий иначе, неверен в ограниченном окружении.
- Выделение в самом обработчике отказа. Пиши в `stderr` готовой строкой, как в примере.

## Арены

### Выделяй объекты одного времени жизни из арены

Арена выдаёт память сдвигом одного указателя и освобождает всё одной операцией, поэтому не нужно отслеживать владение и вызывать `free` для каждого объекта. Подходит для данных, живущих до конца запроса, разбора файла или одной фазы алгоритма: все выделения этапа берутся из арены, а в конце она освобождается целиком.

Арена состоит из двух указателей: `beg` указывает на начало свободного места, `end` на его конец; выделение выравнивает `beg`, проверяет остаток, сдвигает указатель и возвращает обнулённую память. Владелец объектов арены она сама, а блок, из которого она нарезана, освобождает тот, кто его выделил.

```c
/* arena.h */
#ifndef ARENA_H
#define ARENA_H
#include <stddef.h>

typedef struct { char *beg, *end; } arena;

arena arena_init(void *buf, size_t cap);
void *arena_alloc(arena *a, size_t size, size_t align, size_t count);

#define NEW(a, T, n) ((T *)arena_alloc((a), sizeof(T), alignof(T), (n)))
#endif
```

```c
/* arena.c */
#include "arena.h"
#include <assert.h>
#include <stdint.h>
#include <stdlib.h>
#include <string.h>

arena arena_init(void *buf, size_t cap) {
    char *p = buf;
    return (arena){p, p + cap};
}

void *arena_alloc(arena *a, size_t size, size_t align, size_t count) {
    assert(align && (align & (align - 1)) == 0);
    size_t pad = -(uintptr_t)a->beg & (align - 1);
    size_t room = (size_t)(a->end - a->beg);
    if (pad > room || (count && size > (room - pad) / count)) abort();
    char *p = a->beg + pad;
    a->beg = p + size * count;
    return memset(p, 0, size * count);
}
```

Нехватку места арена трактует как фатальную: проверять результат на `nullptr` не нужно, размер блока выбирают по худшему случаю.

#### Подводные камни

- Деструкторов нет. Объекты с внешними ресурсами (дескрипторы, память из `malloc` внутри объекта) закрывай явно до освобождения арены.
- Висячие указатели. После освобождения арены указатели на её объекты недействительны; не сохраняй их в долгоживущих структурах.
- Выравнивание. `align` обязан быть степенью двойки, иначе сдвиг неверен (в отладочной сборке ловит `assert`); `alignof(T)` в `NEW` это соблюдает.

### Передавай арену по значению, когда нужна временная память

Копия заголовка арены даёт функции собственный указатель выделения поверх того же блока, поэтому всё, что функция выделила для промежуточных вычислений, исчезает при её возврате, а арена вызывающего остаётся нетронутой. Это замена `alloca` и массивам переменной длины: размер ограничен блоком арены, а не стеком.

```c
/* main.c */
#include <stdio.h>
#include <stdlib.h>
#include "arena.h"

static int sum_squares(arena scratch, int n) {
    int *sq = NEW(&scratch, int, (size_t)n);
    int sum = 0;
    for (int i = 0; i < n; i++) { sq[i] = i * i; sum += sq[i]; }
    return sum;
}

int main(void) {
    size_t cap = 1 << 12;
    char *mem = malloc(cap);
    if (!mem) abort();
    arena a = arena_init(mem, cap);
    int *keep = NEW(&a, int, 1); /* живёт в арене вызывающего */
    *keep = 1;
    printf("%d\n", sum_squares(a, 10)); /* вывод: 285 */
    printf("%d\n", sum_squares(a, 10) + *keep); /* вывод: 286 */
    free(mem); /* одним free освобождены все выделения арены */
    return 0;
}
```

Две живые копии одной арены выделяют из одного и того же места и перезаписывают друг друга, поэтому копию передают вниз по стеку вызовов и не используют параллельно с оригиналом.

## Срезы

### Передавай указатель вместе с длиной как один тип

Пара «указатель и длина» описывает диапазон байт целиком, поэтому её передают как одно значение, а не как два параметра, которые легко рассогласовать (длину берут от другого буфера). Тип `str` неизменяем и не владеет памятью: он заимствует чужой буфер (литерал, часть строки, участок арены). Границу задаёт `len`, а не NUL, поэтому срез может быть частью строки и содержать нулевые байты.

```c
#include <stdio.h>
#include <string.h>

typedef struct { const char *ptr; size_t len; } str;

static str str_from(const char *s) { return (str){s, strlen(s)}; }

static int str_eq(str a, str b) {
    return a.len == b.len && (a.len == 0 || memcmp(a.ptr, b.ptr, a.len) == 0);
}

/* str_cut: часть до первого sep; в *tail остаток после него.
 * Без sep возвращает s целиком, а *tail пуст. Выделений нет. */
static str str_cut(str s, char sep, str *tail) {
    const char *at = s.len ? memchr(s.ptr, sep, s.len) : nullptr;
    if (!at) {
        *tail = (str){};
        return s;
    }
    size_t n = (size_t)(at - s.ptr);
    *tail = (str){at + 1, s.len - n - 1};
    return (str){s.ptr, n};
}

int main(void) {
    str line = str_from("host=example.org");
    str val, key = str_cut(line, '=', &val);
    printf("%.*s -> %.*s\n", (int)key.len, key.ptr, (int)val.len, val.ptr); /* вывод: host -> example.org */
    printf("%d\n", str_eq(key, str_from("host"))); /* вывод: 1 */
    str raw = {"a\0b", 3};
    printf("%zu %zu\n", raw.len, strlen(raw.ptr)); /* вывод: 3 1 */
    return 0;
}
```

Разбор на срезах не выделяет память: результат указывает внутрь исходного буфера. Строковые операции над срезами, форматирование и построение строк: [строки и буферы](05-strings-and-buffers.md).

#### Подводные камни

- Срез не владеет. После `free` исходного буфера, его `realloc` или освобождения арены срез висит; не храни его дольше владельца.
- Пустой срез может иметь `ptr == nullptr`, а `mem*` с `nullptr` при нулевой длине неопределены ([типы и UB](02-types-and-ub.md)): проверяй `len == 0` до вызова, как в `str_eq` и `str_cut`.
- Вычитание и сравнение указателей определены только внутри одного массива или блока: `at - s.ptr` верно, потому что обе стороны указывают в один срез; разность и сравнение указателей из разных блоков или арен неопределены.
- `s.ptr` в `printf("%s")` или `strlen` читается до первого NUL, то есть за конец среза; печатай `%.*s` с `(int)s.len` или `fwrite`.
- API, которому нужна C-строка. Из среза её получают копией с добавленным NUL (из арены или буфера), а не записью нуля в неизменяемый буфер.

## Коротко

### Счётчик ссылок для совместного владения

Когда последним пользователем объекта может оказаться любой из нескольких владельцев, объект хранит счётчик: `ref` увеличивает его, `unref` уменьшает и освобождает объект на нуле; передача указателя без `ref` означает заимствование. Если объект разделяют потоки, счётчик атомарный, а уменьшение идёт с `acq_rel`: поток, обнуливший счётчик, обязан увидеть все записи в объект, сделанные другими владельцами до их `unref` (release у их уменьшений, acquire у последнего), иначе с `relaxed` `free` может опередить чужие записи; увеличению хватает `relaxed`. В однопоточном коде достаточно обычного целого. Циклические ссылки счётчиком не освобождаются: один из участников цикла держит слабую ссылку без `ref`.

```c
#include <stdatomic.h>
#include <stdlib.h>

typedef struct { atomic_size_t rc; /* данные */ } obj; /* создаётся с rc = 1 */

obj *obj_ref(obj *o) {
    atomic_fetch_add_explicit(&o->rc, 1, memory_order_relaxed);
    return o;
}

void obj_unref(obj *o) {
    if (o && atomic_fetch_sub_explicit(&o->rc, 1, memory_order_acq_rel) == 1) free(o);
}
```

### Гибкий массив в конце структуры

Заголовок и элементы лежат в одном блоке: структура заканчивается массивом без размера, а блок выделяют размером структуры плюс элементы, что экономит одну аллокацию и один уровень косвенности. Присваивание структуры копирует только заголовок: после `*b = *a` элементы `b` остаются прежними, а `sizeof` структуры их не учитывает, поэтому копию делают новым выделением и `memcpy`. Расширение `int v[] __attribute__((counted_by(n)))` связывает массив с полем-счётчиком: Clang 19 и 20 используют его в `-fsanitize=array-bounds`, а GCC 14.2 атрибут не знает (`__has_attribute` даёт 0), поэтому его включают макросом по условию.

```c
#include <stdckdint.h>
#include <stdlib.h>

typedef struct { size_t n; int v[]; } ints;

ints *ints_create(size_t n) {
    size_t bytes;
    if (ckd_mul(&bytes, n, sizeof(int)) || ckd_add(&bytes, bytes, sizeof(ints))) return nullptr;
    ints *p = calloc(1, bytes);
    if (p) p->n = n; /* счётчик задают до обращения к v */
    return p;
}
```

### Пулы и списки свободных объектов

Если один и тот же тип часто создают и уничтожают, освобождённые объекты складывают в односвязный список и берут из него: выделение и возврат занимают по одной операции с указателем, фрагментация не растёт. Следующий указатель хранят прямо в освобождённом объекте. Платой служит то, что память не возвращается системе до `pool_clear` (обход списка с `free` каждого элемента), а реюз требует повторной инициализации объекта.

```c
#include <stdlib.h>

typedef struct item { struct item *next; char data[56]; } item;
typedef struct { item *free_list; } pool;

item *pool_acquire(pool *p) {
    item *it = p->free_list;
    if (!it) return calloc(1, sizeof *it);
    p->free_list = it->next;
    *it = (item){}; /* реюз: возвращаем нулевое состояние */
    return it;
}

void pool_release(pool *p, item *it) { it->next = p->free_list; p->free_list = it; }
```

### Замена аллокатора без правки кода

Другой аллокатор (например mimalloc) подключают подменой `malloc`/`free`: `LD_PRELOAD=libmimalloc.so ./app`, компоновкой с библиотекой или явными вызовами `mi_malloc`/`mi_free`. Блок, выделенный одним аллокатором, нельзя освобождать другим, поэтому выбор делают для всей программы, включая её библиотеки; выигрыш измеряют на реальной нагрузке ([производительность](13-performance.md)).

## Что ещё стоит знать

Для выравнивания больше стандартного (SIMD, кэш-линия) есть `aligned_alloc(align, size)`: блок освобождается обычным `free`, а размер разумно брать кратным выравниванию; `realloc` такого блока выравнивание не сохраняет (в glibc блок после роста может потерять выравнивание), поэтому растущий блок выделяют заново и копируют. Выделение на стеке через `alloca` и массивы переменной длины не сообщает об отказе (переполнение стека убивает процесс), поэтому для размеров из внешних данных используй арену или `malloc`. В C23 появились `free_sized`, `free_aligned_sized` и `memset_explicit`; в glibc 2.39 их нет, вместо последней используй `explicit_bzero` перед освобождением секретов ([безопасность](12-security.md)). В glibc переменная окружения `MALLOC_PERTURB_` заполняет выделяемую и освобождаемую память шаблоном, что выявляет чтение неинициализированного и освобождённого без санитайзера.

# Строки и буферы

## Срезы

### Держи строки срезами, а NUL-строки оставляй на границе с libc

Тип `str` и принцип «указатель вместе с длиной» описаны в [памяти и владении](04-memory-ownership.md); здесь операции над срезами: префикс, поиск, обрезка и разбиение. Все они принимают и возвращают срезы и ничего не выделяют. NUL-строка нужна только там, где её требует libc или системный вызов (`fopen`, `getenv`, `strtol`, `printf("%s")`), и именно на этой границе делается копия.

```c
/* str.h */
#ifndef STR_H
#define STR_H
#include <stdbool.h>
#include <stddef.h>

typedef struct { const char *ptr; size_t len; } str;

str str_from(const char *s);
bool str_starts(str s, str prefix);
bool str_find(str s, str needle, size_t *at);
str str_trim(str s);
str str_token(str *rest, char sep);
#endif
```

```c
/* str.c */
#include "str.h"
#include <ctype.h>
#include <string.h>

str str_from(const char *s) { return (str){s, strlen(s)}; }

bool str_starts(str s, str prefix) {
    return prefix.len <= s.len && (prefix.len == 0 || memcmp(s.ptr, prefix.ptr, prefix.len) == 0);
}

bool str_find(str s, str needle, size_t *at) {
    if (needle.len == 0) { *at = 0; return true; }
    for (size_t i = 0; needle.len <= s.len && i <= s.len - needle.len; i++)
        if (memcmp(s.ptr + i, needle.ptr, needle.len) == 0) { *at = i; return true; }
    return false;
}

str str_trim(str s) {
    while (s.len && isspace((unsigned char)s.ptr[0])) { s.ptr++; s.len--; }
    while (s.len && isspace((unsigned char)s.ptr[s.len - 1])) s.len--;
    return s;
}

/* str_token: поле до sep, *rest сдвигается за разделитель; пустой *rest значит конец */
str str_token(str *rest, char sep) {
    str s = *rest;
    const char *at = s.len ? memchr(s.ptr, sep, s.len) : nullptr;
    if (!at) { *rest = (str){s.ptr + s.len, 0}; return s; }
    size_t n = (size_t)(at - s.ptr);
    *rest = (str){at + 1, s.len - n - 1};
    return (str){s.ptr, n};
}
```

```c
/* main.c */
#include <stdio.h>
#include "str.h"

int main(void) {
    str rest = str_from("host = example.org\n# note\n port=8080 \n"), line;
    int fields = 0;
    while (rest.len) {
        line = str_trim(str_token(&rest, '\n'));
        size_t eq;
        if (line.len == 0 || str_starts(line, str_from("#")) || !str_find(line, str_from("="), &eq))
            continue;
        str key = str_trim((str){line.ptr, eq});
        str val = str_trim((str){line.ptr + eq + 1, line.len - eq - 1});
        printf("[%.*s]=[%.*s]\n", (int)key.len, key.ptr, (int)val.len, val.ptr);
        /* вывод: [host]=[example.org] */
        /* вывод: [port]=[8080] */
        fields++;
    }
    printf("%d\n", fields); /* вывод: 2 */
    return 0;
}
```

Разбиение через `str_token` не меняет исходный текст, не хранит скрытого состояния и работает с константными данными; пустой хвост после последнего разделителя поля не даёт. Когда срез нужно передать в libc, из арены ([арены](04-memory-ownership.md)) берут NUL-копию: `str_cstr(arena *, str)` проверяет `memchr`, нет ли нулевого байта внутри среза (иначе возвращает `nullptr`: libc увидела бы другую строку), выделяет в арене `s.len + 1` байт, копирует `memcpy` и возвращает указатель, освобождать который не нужно. Арена возвращает обнулённую память, поэтому завершающий нуль уже стоит на месте.

#### Подводные камни

- Срез передают `strlen`, `strcmp`, `puts` или `%s`: они ищут нуль и читают за концом данных. Такую границу проходят только через `str_cstr` или `%.*s`, а место под терминатор считают явно: размер буфера равен длине плюс один.
- Запись в строковый литерал неопределена: `char *s = "abc"; s[0] = 'x';` падает, потому что литерал лежит в памяти только для чтения. Изменяемую строку заводят массивом (`char s[] = "abc"`), а читаемую через `const char *`.
- `strtok` пишет нули в исходную строку, хранит состояние между вызовами, не работает с константными данными и не потокобезопасна. Разбивай через `str_token` или `memchr`.
- Нулевой байт внутри данных (имя файла, значение заголовка) при передаче в libc обрезает строку: проверка `"file.txt\0.png"` проходит по длине, а `fopen` открывает `file.txt`. Копирующая функция на границе отвергает такой срез, как `str_cstr`.
- Запись нуля в буфер среза ради получения C-строки портит соседний срез: следующее поле, сам разделитель. Копируй, а не завершай на месте.
- `memcmp`, `memchr` и `memcpy` с `nullptr` и нулевой длиной неопределены, поэтому в `str_starts` и `str_find` длина проверяется до вызова ([типы и UB](03-types-and-ub.md)).
- `strcmp` и `memcmp` дают порядок по байтам, а не по алфавиту: для сортировки текста для человека нужны правила Unicode и локали, для ключей поиска байтового порядка достаточно.

## Форматирование

### Форматируй в буфер ограниченного размера, проверяй усечение и передавай формат литералом

`snprintf` никогда не пишет за границу буфера, но возвращает длину, которая получилась бы без усечения, поэтому только сравнение результата с размером отличает полную запись от обрезанной. Тот же вызов с нулевым размером и `nullptr` возвращает нужную длину: сначала узнают размер, потом выделяют буфер ровно под результат (приём двухфазного вызова для своих API: [буфер от вызывающего](07-api-and-modules.md)). Формат всегда пишут литералом: строка, пришедшая из данных, позволяет читать стек и писать в память через `%n`, а компилятор проверяет типы аргументов только у литерала.

Своя обёртка над `vsnprintf` получает атрибут `format`: расширение GCC/Clang, поэтому пример собирается без `-Wpedantic`. Он включает проверку литерала и аргументов у каждого вызова обёртки, и вместе с `-Wformat=2 -Werror` ошибка в формате становится ошибкой сборки. Для переносимого кода атрибут прячут за макросом по `__has_attribute(format)`.

```c
#include <inttypes.h>
#include <stdarg.h>
#include <stdio.h>
#include <stdlib.h>

typedef struct { const char *ptr; size_t len; } str;

char *fmt_dup(const char *fmt, ...) __attribute__((format(printf, 1, 2)));

/* fmt_dup: результат в куче, освобождает вызывающий; nullptr при нехватке памяти или ошибке формата */
char *fmt_dup(const char *fmt, ...) {
    va_list ap, cp;
    va_start(ap, fmt);
    va_copy(cp, ap);
    int n = vsnprintf(nullptr, 0, fmt, ap);
    va_end(ap);
    char *s = nullptr;
    if (n >= 0 && (s = malloc((size_t)n + 1)))
        vsnprintf(s, (size_t)n + 1, fmt, cp);
    va_end(cp);
    return s;
}

int main(int argc, char **argv) {
    const char *who = argc > 1 ? argv[1] : "alice";
    char small[8];
    int n = snprintf(small, sizeof small, "%d:%s", 41 + argc, who);
    printf("%d %d %s\n", n < 0, n >= (int)sizeof small, small); /* вывод: 0 1 42:alic */

    str name = {"alice!", 5};
    char *s = fmt_dup("%zu:%" PRIu64 ":%.*s", sizeof small, (uint64_t)42, (int)name.len, name.ptr);
    if (!s) abort();
    puts(s); /* вывод: 8:42:alice */
    free(s);
    return 0;
}
```

Копия `va_list` обязательна: после первого `vsnprintf` исходный список использовать нельзя, а второй проход должен видеть те же аргументы. Размеры печатают `%zu`, `%td`, целые фиксированной ширины через `PRIu64` и `PRId64` из `<inttypes.h>` (`%d` и `%lu` верны лишь на одной платформе), срез как `%.*s` с `(int)s.len`.

#### Подводные камни

- Результат `snprintf` не проверяют: усечённый путь, имя или запрос молча уходит дальше. Всегда сравнивай с размером, отрицательный результат означает ошибку кодирования.
- Возврат `snprintf` принят за число записанных байт и накапливается в `len` (`len += snprintf(buf + len, sizeof buf - len, ...)`): после усечения `len` превышает размер, `sizeof buf - len` оборачивается в огромное число, и следующий вызов пишет за границу (UB). Накопление делает построитель из следующего раздела.
- Размер берут как `sizeof` от параметра-указателя: получается размер указателя, а не буфера. Размер передают отдельным параметром.
- `printf(s)` и `fprintf(f, s)` для строки из данных. Используй `printf("%s", s)` или `fputs(s, stdout)`; `-Wformat=2` включает `-Wformat-nonliteral` и `-Wformat-security`, которые ловят такие вызовы.
- Обёртка над `vsnprintf` без атрибута `format`: Clang под `-Wformat=2` сразу сообщает о нелитеральном формате, GCC молчит, а вызовы обёртки не проверяются ни тем, ни другим.
- `%.*s` останавливается на первом нулевом байте, даже если точность больше: срез с нулями внутри печатают через `fwrite`. Приведение `(int)s.len` для длины больше `INT_MAX` даёт мусор, длинные срезы тоже печатают через `fwrite`.
- `%s` с `nullptr` не определён: glibc печатает `(null)`, но на это не рассчитывай.
- `sprintf` и `vsprintf` не принимают размер вообще; запрещай их в проекте.

## Построитель строк

### Собирай строку растущим буфером, а не цепочкой strcat

Растущий буфер знает свою длину и ёмкость, поэтому добавление стоит амортизированно одну копию нового фрагмента, а цепочка `strcat` каждый раз заново ищет конец строки (квадратичное время) и ничего не знает о границе. Построитель здесь всегда завершён нулём: `sb.data` можно передать в libc сразу, а длина хранится отдельно и остаётся главной, так что нулевые байты внутри допустимы. Нулевое состояние `{}` корректно (`data == nullptr`, [память и владение](04-memory-ownership.md)); для него `sb_cstr` возвращает пустую строку.

```c
/* sb.h */
#ifndef SB_H
#define SB_H
#include <stddef.h>

typedef struct { char *data; size_t len, cap; } sb;

/* sb_append - добавляет n байт; data заимствуется, допустим nullptr при n == 0.
 * Возврат: 0 или -ENOMEM; при ошибке содержимое не изменено.
 * Не потокобезопасна для одного построителя. Инвалидирует указатели на sb.data. */
int sb_append(sb *b, const char *data, size_t n);

/* sb_reserve - гарантирует место ещё под extra байт и завершающий NUL; те же коды возврата. */
int sb_reserve(sb *b, size_t extra);

/* sb_cstr - заимствованная NUL-строка, "" для пустого. sb_clear - освобождает буфер. */
const char *sb_cstr(const sb *b);
void sb_clear(sb *b);
#endif
```

```c
/* sb.c */
#include "sb.h"
#include <errno.h>
#include <stdckdint.h>
#include <stdlib.h>
#include <string.h>

int sb_reserve(sb *b, size_t extra) {
    size_t need;
    if (ckd_add(&need, b->len, extra) || ckd_add(&need, need, (size_t)1)) return -ENOMEM;
    if (need <= b->cap) return 0;
    size_t cap = b->cap ? b->cap : 16;
    while (cap < need)
        if (ckd_mul(&cap, cap, (size_t)2)) return -ENOMEM;
    char *p = realloc(b->data, cap);
    if (!p) return -ENOMEM;
    b->data = p;
    b->cap = cap;
    return 0;
}

int sb_append(sb *b, const char *data, size_t n) {
    int rc = sb_reserve(b, n);
    if (rc != 0) return rc;
    if (n) memcpy(b->data + b->len, data, n);
    b->len += n;
    b->data[b->len] = '\0';
    return 0;
}

const char *sb_cstr(const sb *b) { return b->data ? b->data : ""; }

void sb_clear(sb *b) {
    free(b->data);
    *b = (sb){};
}
```

```c
/* main.c */
#include <stdio.h>
#include <stdlib.h>
#include "sb.h"

int main(void) {
    sb b = {};
    printf("[%s]\n", sb_cstr(&b)); /* вывод: [] */
    for (int i = 0; i < 3; i++) {
        char digit = (char)('0' + i * i);
        if ((i && sb_append(&b, ",", 1) != 0) || sb_append(&b, &digit, 1) != 0) abort();
    }
    if (sb_append(&b, ";end", 4) != 0) abort();
    printf("%s %zu\n", sb_cstr(&b), b.len); /* вывод: 0,1,4;end 9 */
    sb_clear(&b);
    printf("[%s] %zu\n", sb_cstr(&b), b.len); /* вывод: [] 0 */
    return 0;
}
```

После `sb_clear` построитель возвращается в нулевое состояние и пригоден к повторному использованию. Структура та же, что у растущего массива из [контейнеров](11-containers-and-generics.md), с постоянным нулём в конце.

#### Подводные камни

- Указатель или срез на содержимое `b->data`, сохранённый до добавления. Следующий `sb_append` может переместить буфер (`realloc`), и указатель повиснет; храни смещения и перебирай их после сборки.
- Рост на константу вместо удвоения даёт квадратичное время; удвоение с проверкой `ckd_mul` и `ckd_add` защищает ещё и от переполнения размера при огромных входных данных.
- `realloc` напрямую в `b->data`: при отказе указатель теряется. Результат берут во временную переменную, как в `sb_reserve`.
- Форматированное добавление пишут так же, как `fmt_dup` из предыдущего раздела: `vsnprintf` с нулевым размером даёт длину, `sb_reserve` место, второй `vsnprintf` с копией `va_list` пишет в буфер.
- Построитель поверх арены: при росте старый блок остаётся в арене до её освобождения; резервируй размер заранее.

## Копирование и числа

### Копируй с известным размером приёмника, не пользуйся strcpy, strcat и strncpy

`strcpy` и `strcat` не знают размера приёмника, поэтому длинный источник переполняет буфер, а `strncpy` создана для полей фиксированной ширины, а не для строк: при усечении она не ставит нуль, а при короткой строке дописывает нулями весь остаток буфера. Для строк с проверкой усечения служат `strlcpy` и `strlcat`: они завершают результат нулём и возвращают длину, которая получилась бы без усечения, как `snprintf`. Они есть в glibc 2.38 и новее (объявлены при `_DEFAULT_SOURCE`, входящем в `_GNU_SOURCE`), но не входят в C23 и могут отсутствовать в другой libc; тогда переносимый эквивалент `snprintf(dst, size, "%s", src)` с той же проверкой результата. Если длина источника известна, надёжнее всего проверка длины и `memcpy`: приёмнику нужно место под длину плюс завершающий нуль.

```c
#define _DEFAULT_SOURCE
#include <stdio.h>
#include <string.h>

int main(void) {
    char name[8];
    size_t n = strlcpy(name, "alexander", sizeof name);
    printf("%d %s\n", n >= sizeof name, name); /* вывод: 1 alexand */

    char path[16] = "/tmp/";
    n = strlcat(path, "very_long_filename", sizeof path);
    printf("%zu %s\n", n, path); /* вывод: 23 /tmp/very_long_ */

    char s[] = "abcdef";
    memmove(s, s + 1, strlen(s)); /* области перекрываются; копируется и завершающий NUL */
    puts(s); /* вывод: bcdef */
    return 0;
}
```

#### Подводные камни

- `memcpy` с перекрывающимися областями (сдвиг содержимого буфера, удаление префикса) неопределён, даже если «на практике работает»: перекрывающиеся области копируют только через `memmove`, как в примере.
- `strncpy(name, "abcdef", sizeof name)` в поле из четырёх байт не ставит нуль, и следующий `strlen` читает за буфером. `strncpy` годится только для полей фиксированной ширины с заполнением нулями (метка, код), и такое поле не является C-строкой.
- Результат `strlcpy` и `strlcat` игнорируют: усечённое имя или путь молча уходит дальше (в проверках доступа это обход). Сравнивай с размером приёмника.
- `strlcat` к приёмнику, в котором нет нуля в пределах размера: функция ничего не пишет и возвращает размер плюс длину источника. Приёмник инициализируют всегда.
- `strcat` в цикле: каждый вызов заново ищет конец. Копи через построитель или держи текущую длину сам.
- `memcpy(dst, src, n)` с `n`, пришедшим из данных, без проверки `n <= cap` переполняет приёмник так же, как `strcpy`; проверка идёт до копирования.

### Разбирай числа через strtol и strtod и проверяй всё

`atoi`, `atof` и `sscanf("%d")` не сообщают об ошибке: на мусоре они возвращают нуль, а переполнение у `atoi` и `sscanf` не определено. `strtol` и родственные разбирают число, возвращают границу разобранного и сообщают о выходе из диапазона, но принять результат можно только после четырёх проверок: пустая строка и ведущие пробелы, `endptr` не равен началу (были цифры), `*endptr` равен нулю (строка разобрана полностью), `errno` не `ERANGE`. Размер `long` и целевого типа может различаться, поэтому границы диапазона принимает сама функция разбора. Перед вызовом `errno` обнуляют, потому что успешный вызов его не сбрасывает.

```c
/* parse.h */
#ifndef PARSE_H
#define PARSE_H

/* parse_long - строгий разбор десятичного числа в [lo, hi].
 * parse_double - строгий разбор конечного числа с плавающей точкой.
 * Возврат: 0, -EINVAL (пусто, пробел в начале, мусор после числа, inf и nan)
 * или -ERANGE (вне диапазона); при ошибке *out не изменяется. */
int parse_long(const char *s, long lo, long hi, long *out);
int parse_double(const char *s, double *out);
#endif
```

```c
/* parse.c */
#include "parse.h"
#include <ctype.h>
#include <errno.h>
#include <math.h>
#include <stdlib.h>

int parse_long(const char *s, long lo, long hi, long *out) {
    if (!*s || isspace((unsigned char)*s)) return -EINVAL;
    char *end;
    errno = 0;
    long v = strtol(s, &end, 10);
    if (end == s || *end != '\0') return -EINVAL;
    if (errno == ERANGE || v < lo || v > hi) return -ERANGE;
    *out = v;
    return 0;
}

int parse_double(const char *s, double *out) {
    if (!*s || isspace((unsigned char)*s)) return -EINVAL;
    char *end;
    errno = 0;
    double v = strtod(s, &end);
    if (end == s || *end != '\0') return -EINVAL;
    if (errno == ERANGE) return -ERANGE;
    if (!isfinite(v)) return -EINVAL;
    *out = v;
    return 0;
}
```

```c
/* main.c */
#include <errno.h>
#include <stdio.h>
#include "parse.h"

static const char *why(int rc) { return rc == 0 ? "ok" : rc == -ERANGE ? "range" : "bad"; }

static void show(const char *s) {
    long v = 0;
    int rc = parse_long(s, 0, 255, &v);
    printf("%s %ld\n", why(rc), v);
}

int main(void) {
    show("42"); /* вывод: ok 42 */
    show("300"); /* вывод: range 0 */
    show("12abc"); /* вывод: bad 0 */
    show(" 5"); /* вывод: bad 0 */
    show("99999999999999999999"); /* вывод: range 0 */
    double d = 0;
    printf("%s %s\n", why(parse_double("2.5e3", &d)), why(parse_double("nan", &d))); /* вывод: ok bad */
    printf("%g\n", d); /* вывод: 2500 */
    return 0;
}
```

Основание `10` задают явно: `0` включает восьмеричные и шестнадцатеричные литералы, и `"010"` превращается в 8. Для среза сначала делают NUL-копию (`str_cstr` из раздела о срезах), строку из `fgets` очищают от `'\n'`, иначе полнота разбора не пройдёт.

#### Подводные камни

- `strtoul` и `strtoull` принимают знак минус и возвращают отрицательное число по модулю `ULONG_MAX + 1`: `"-1"` даёт максимальное значение. Первый символ проверяют отдельно.
- `errno` не обнулён перед вызовом: остаток от прежней ошибки выдаёт `ERANGE` у корректного числа.
- Единственная проверка `errno`: на `"abc"` она ничего не покажет, отсутствие цифр видно только по `end == s`.
- `strtod` принимает `inf`, `nan` и шестнадцатеричную запись `0x1p3`; в конфигурации и протоколе их обычно не ждут. Результат `ERANGE` у `strtod` бывает и при потере точности у очень малых чисел.
- Результат `long` присваивают `int` без проверки диапазона: на 64-битной платформе значение обрезается молча ([преобразования типов](03-types-and-ub.md)); для `int64_t` берут `strtoll`.

## Ввод и символы

### Читай ввод по результату чтения, а не по feof

Признак конца файла выставляется только после неудачного чтения, поэтому `feof` как условие цикла делает лишний проход с устаревшими данными, а цикл должен зависеть от возврата самой функции чтения. После выхода из цикла `feof` и `ferror` различают конец данных и ошибку. Результат `fgetc` и `getchar` хранят в `int`: он принимает все значения `unsigned char` и отдельное `EOF`, а в `char` байт `0xFF` на платформе со знаковым `char` совпадает с `EOF`, и цикл обрывается посреди данных (на платформе с беззнаковым `char` условие не срабатывает никогда). Для строк произвольной длины из доверенного источника берут `getline`: он сам растит буфер, возвращает длину и работает с нулевыми байтами; примеры читают из памяти через `fmemopen`, чтобы обойтись без `stdin`.

```c
#define _GNU_SOURCE
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

int main(void) {
    char text[] = "alpha\nbe\0ta\n\ngamma";
    FILE *f = fmemopen(text, sizeof text - 1, "r");
    if (!f) abort();
    char *line = nullptr;
    size_t cap = 0, total = 0;
    int lines = 0, nul = 0;
    for (ssize_t n; (n = getline(&line, &cap, f)) != -1; lines++) {
        size_t len = (size_t)n;
        if (len && line[len - 1] == '\n') len--;
        total += len;
        nul += strlen(line) != (size_t)n && memchr(line, '\0', len);
    }
    printf("%d %zu %d %d\n", lines, total, nul, ferror(f) != 0); /* вывод: 4 15 1 0 */
    free(line);
    fclose(f);
    return 0;
}
```

Буфер `line` общий для всех вызовов: `getline` переиспользует его и растит, поэтому освободить его нужно один раз после цикла, даже когда последний вызов вернул `-1`. Длину строки берут из возврата, а не из `strlen`. Строка без `'\n'` в конце бывает у последней строки файла. Для недоверенного ввода `getline` не годится: он читает строку до конца и растит буфер до любого размера, поэтому проверка `n` после возврата опаздывает. Читай `fgets` в буфер фиксированного размера и при строке длиннее лимита отбрасывай остаток до `'\n'` (чтение на уровне дескрипторов, частичные чтения и неблокирующий ввод: [системный уровень](13-system-io.md)).

Правильный побайтовый цикл `while ((c = fgetc(f)) != EOF)` с `int c` проходит и байт `0xFF`; признак конца проверяют только после выхода из цикла. Две типичные ошибки цикла чтения в двух функциях:

```c
/* Ошибка: char не отличает EOF от байта 0xFF, feof как условие цикла даёт лишний проход */
#include <stdio.h>

void dump_bytes(FILE *f) {
    char c;
    while ((c = (char)fgetc(f)) != EOF)
        putchar(c);
}

void dump_lines(FILE *f) {
    char line[64];
    while (!feof(f)) {
        fgets(line, sizeof line, f);
        fputs(line, stdout);
    }
}
```

Цикл в `dump_lines` на последней итерации не получает данных: `fgets` вернула нулевой указатель, а `line` хранит прежнюю строку, и она выводится повторно.

Успешный `fgets` не гарантирует непустую C-строку: если ввод начинается с нулевого байта, `strlen(buf)` равна нулю, и типичная очистка `buf[strlen(buf) - 1] = '\0'` пишет по индексу `SIZE_MAX` (UB). Правильная очистка не зависит от длины: `buf[strcspn(buf, "\n")] = '\0'`.

#### Подводные камни

- `fgets` с буфером меньше строки возвращает её начало без `'\n'`, остаток придёт со следующим вызовом. Отсутствие `'\n'` значит либо усечение, либо последнюю строку без перевода; решай по наличию `'\n'` и `feof`.
- `ferror` не проверена после цикла: сбой чтения выглядит как нормальный конец данных, и программа молча обрабатывает часть входа. Проверяй `ferror` до того, как считать вход полным.
- `gets` удалена из C11, `scanf("%s")` без ширины переполняет буфер: ширину задают в формате (`"%15s"`), а для строк лучше `getline`.
- Смешивание буферизованного ввода (`fgetc`, `getline`) и чтения того же дескриптора через `read` теряет данные, спрятанные в буфере `FILE`.

### Приводи символ к unsigned char для ctype и храни UTF-8 как байты

Функции `<ctype.h>` определены для значений `unsigned char` и `EOF`, а обычный `char` на платформе со знаковым `char` даёт отрицательное число для байтов выше `0x7F`: в glibc это терпится (таблица принимает отрицательные индексы), а в других реализациях это неопределённое поведение или выход за таблицу. Приведение пишут всегда: `isdigit((unsigned char)c)`. Знаковость `char` определяется платформой (на x86 знаковый, на ARM под Linux беззнаковый), поэтому и сравнения `c < 0x80`, и использование `c` индексом, и вывод в `int` ведут себя по-разному; для байтовых данных берут `unsigned char` или `uint8_t`.

UTF-8 хранят и передают как последовательность байт, как любые другие строки: байты ASCII (разделители, пробелы, кавычки) никогда не встречаются внутри многобайтовой последовательности, поэтому разбиение по ним через `memchr` безопасно. Проверяют валидность один раз, на входе; дальше внутри программы текст считается корректным. Длина `strlen` и ширина `%-10s` считают байты, а не символы; обрезать по байтам можно только на границе последовательности.

```c
#include <stdbool.h>
#include <stddef.h>
#include <stdio.h>

typedef struct { const char *ptr; size_t len; } str;

bool utf8_valid(str s) {
    const unsigned char *p = (const unsigned char *)s.ptr;
    for (size_t i = 0, n; i < s.len; i += n) {
        unsigned char c = p[i];
        n = c < 0x80 ? 1 : c >= 0xC2 && c <= 0xDF ? 2 : c >= 0xE0 && c <= 0xEF ? 3
          : c >= 0xF0 && c <= 0xF4 ? 4 : 0;
        if (n == 0 || n > s.len - i) return false;
        for (size_t k = 1; k < n; k++)
            if ((p[i + k] & 0xC0) != 0x80) return false;
        if (n == 3 && ((c == 0xE0 && p[i + 1] < 0xA0) || (c == 0xED && p[i + 1] > 0x9F))) return false;
        if (n == 4 && ((c == 0xF0 && p[i + 1] < 0x90) || (c == 0xF4 && p[i + 1] > 0x8F))) return false;
    }
    return true;
}

/* utf8_prefix: наибольшая длина <= max, не разрезающая последовательность */
size_t utf8_prefix(str s, size_t max) {
    if (s.len <= max) return s.len;
    while (max > 0 && ((unsigned char)s.ptr[max] & 0xC0) == 0x80) max--;
    return max;
}

int main(void) {
    str ok = {"na\xc3\xafve \xe2\x82\xac", 10};
    str overlong = {"\xc0\x80", 2}, surrogate = {"\xed\xa0\x80", 3}, cut = {"\xe2\x82", 2};
    printf("%d%d%d%d\n", utf8_valid(ok), utf8_valid(overlong), utf8_valid(surrogate), utf8_valid(cut)); /* вывод: 1000 */
    printf("%zu %zu\n", utf8_prefix(ok, 3), utf8_prefix(ok, 8)); /* вывод: 2 7 */
    return 0;
}
```

Проверка отвергает короткие формы (`0xC0 0x80`), суррогаты (`0xED 0xA0..`), значения выше `U+10FFFF` и оборванные последовательности. Нормализация, регистр и ширина символа по таблицам Unicode не делаются побайтово: для них берут библиотеку (см. «Что ещё стоит знать»).

#### Подводные камни

- `isalpha`, `toupper`, `isspace` работают по байтам и локали: для байтов выше `0x7F` в UTF-8 локали ничего осмысленного не дают. Разбор протоколов и конфигураций делай явными проверками диапазонов ASCII.
- Обрезка по байтовому лимиту (поле БД, колонка, буфер) посреди последовательности даёт невалидный UTF-8, который падает у следующего потребителя. Используй `utf8_prefix`.
- Валидность проверяют до использования, а не после: невалидные последовательности (короткие формы, суррогаты) могут пропустить проверки путей и имён, написанные для корректного ввода.
- Сравнение по байтам различает составной и разложенный `é`; для равенства «по смыслу» нужна нормализация.
- `c - '0'` для не-ASCII байта в `char` даёт отрицательные значения: приводи к `unsigned char` до арифметики ([целые типы и преобразования](03-types-and-ub.md)).

## Локаль

### Не позволяй локали процесса менять разбор и вывод чисел

`LC_NUMERIC` задаёт десятичный разделитель для `printf("%f")`, `strtod`, `scanf` и `atof`, поэтому программа, правильная на машине разработчика, в окружении с `LANG=de_DE.UTF-8` печатает `3,14` и читает `"3.14"` как `3`, а остаток `.14` считает мусором. Эффект включается вызовом `setlocale` (процесс стартует в локали `"C"`), а вызвать его может не только `main`, но и подключённая библиотека. Серверу и разбору протоколов (JSON, HTTP, конфигурации) числа нужны в одной форме независимо от среды: `setlocale(LC_ALL, "")` в таком процессе не вызывают, а где он нужен для текста (кодировка, сообщения), `LC_NUMERIC` возвращают в `"C"`.

```c
/* Ошибка: формат и разбор чисел зависят от LC_NUMERIC окружения */
#include <locale.h>
#include <stdio.h>
#include <stdlib.h>

int main(void) {
    setlocale(LC_ALL, "");
    printf("%.2f\n", 3.14159);
    char *end;
    double d = strtod("3.14", &end);
    printf("%g [%s]\n", d, end);
    return 0;
}
```

При `LANG=de_DE.UTF-8` (локаль должна быть установлена в системе) этот код печатает `3,14` и `3 [.14]`. Локаль меняется для всего процесса, и `setlocale` не потокобезопасна. Чтобы защитить конкретный участок кода и остальные потоки, создают локаль `"C"` для числовой категории и включают её только для текущего потока (`newlocale`, `uselocale`; под `-std=c23` нужен `_GNU_SOURCE`):

```c
#define _GNU_SOURCE
#include <locale.h>
#include <stdio.h>
#include <stdlib.h>

int main(void) {
    setlocale(LC_ALL, ""); /* где-то в программе локаль включили */
    locale_t c = newlocale(LC_NUMERIC_MASK, "C", (locale_t)0);
    if (!c) abort();
    locale_t old = uselocale(c); /* дальше в этом потоке числа в форме "C" */
    printf("%.2f\n", 3.14159); /* вывод: 3.14 */
    char *end;
    double d = strtod("3.14", &end);
    printf("%g [%s]\n", d, end); /* вывод: 3.14 [] */
    uselocale(old);
    freelocale(c);
    return 0;
}
```

#### Подводные камни

- Библиотека (графическая, локализации), подключённая в сервер, вызывает `setlocale(LC_ALL, "")` в своей инициализации: числа в протоколе меняют форму от окружения. Проверяй `localeconv()->decimal_point` в тесте с `LANG=de_DE.UTF-8`, а на горячем пути заводи локаль потока.
- `setlocale` в многопоточной программе: гонка с чтением форматов в других потоках. Вызывают один раз в начале `main`, до создания потоков, или не вызывают вовсе. Программе с переводом сообщений нужна локаль окружения для текстов, но не для чисел: правило для таких программ дано в [главе про локализацию](18-localization.md).
- Числа для людей (интерфейс) и числа для машин (протоколы, файлы) разделяют: первые форматируют локалью, вторые всегда локалью `"C"`.

## Коротко

### strdup и strndup

Функции `strdup` и `strndup` вошли в C23 и видны под `-std=c23` без макросов; результат освобождает вызывающий. `strndup(p, n)` копирует не более `n` байт, но останавливается на первом нулевом, поэтому срез с нулями внутри ею обрезается молча: для среза выделяй `len + 1` байт и копируй `memcpy`, как в `str_cstr`.

### Const-корректность strchr и strtol

Стандарт C23 требует, чтобы `strchr`, `strstr`, `memchr` и их родственники сохраняли `const` у аргумента, но glibc 2.39 их ещё возвращает как `char *`: присваивание `char *p = strchr(const_s, 'x')` собирается молча и теряет `const`. Результат записывают в `const char *`, а изменяемый указатель берут только из изменяемой строки. У `strtol` и `strtod` параметр `endptr` имеет тип `char **`: для константной строки он всё равно `char *`, и писать через него нельзя. Передача `&end` для `const char *end` на GCC 14 даёт ошибку (`-Wincompatible-pointer-types`), на Clang 19 и 20 предупреждение.

### Атрибут nonstring

Поле фиксированной ширины без нуля (магическое число формата, метка из четырёх байт) не является C-строкой, а GCC под `-Wall` предупреждает о копировании в него через `strncpy` (`-Wstringop-truncation`). Расширение GCC `nonstring` сообщает компилятору о намерении: предупреждение о копировании уходит, а передача такого поля в `strlen` или `%s` получает предупреждение `-Wstringop-overread`. Clang 19 и 20 атрибута не знают (`__has_attribute(nonstring)` равен 0), поэтому его включают по условию. Поле печатают через `%.4s` или `fwrite`, а не `%s`; макрос `NONSTRING` определяют как `__attribute__((nonstring))` под `#if __has_attribute(nonstring)` и пустым иначе.

### Форматы %g, %a и %b

`%g` печатает самое короткое представление при заданном числе значащих цифр (по умолчанию шесть), для точного обратного разбора двойной точности нужно `%.17g`, одинарной `%.9g`. `%a` печатает шестнадцатеричную запись, точную и пригодную для записи в файл без потерь. В C23 добавлен двоичный `%b` (`printf("%b", 5u)` печатает `101`, `%#b` добавляет префикс `0b`): в glibc 2.39 он работает и принимается `-Wformat=2` на всех трёх компиляторах, но ASan (Clang 19 и 20, GCC 14) печатает по нему предупреждение, что делает такой вывод неудобным в тестовой сборке. Для `0.1` `%.17g` даёт `0.10000000000000001`, `%a` даёт `0x1.999999999999ap-4`, `%g` даёт `0.1`.

## Что ещё стоит знать

Для регистра, нормализации (NFC, NFD) и границ графем по правилам Unicode берут библиотеку utf8proc: она работает с UTF-8 байтами напрямую. Динамические строки sds (указатель на `char` с длиной в заголовке перед ним, всегда завершены нулём, нулевые байты допустимы) на росте могут вернуть `nullptr` и переместить строку, поэтому результат изменяющих вызовов присваивают обратно (`s = sdscat(s, ...)`), а при возможном отказе используют промежуточную переменную, как с `realloc`. Широкие символы `wchar_t` и функции `wcs*` для UTF-8 не нужны.

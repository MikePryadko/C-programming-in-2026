# Ошибки и очистка

## Ошибки

### Проверяй ошибки программиста через assert, а ожидаемые отказы возвращай

Ошибка программиста (нарушенный контракт, невозможное состояние) исправляется правкой кода, а не обработкой в рантайме, поэтому её ловит `assert`; отказ, который может случиться у правильной программы (неверный ввод, нет файла, нет памяти), возвращается вызывающему кодом ошибки. `assert` отключается флагом `-DNDEBUG`, и тогда его аргумент не вычисляется вообще: любая проверка, нужная в рабочей сборке, и любой побочный эффект в `assert` не живут. Оставлять ли `assert` в релизе, выбор проекта: включённый превращает нарушенный контракт в немедленное аварийное завершение с указанием строки.

```c
#include <assert.h>
#include <errno.h>
#include <stdio.h>

/* pct: 0..100, проверяет вызывающий */
static int percent_of(int total, int pct) {
    assert(pct >= 0 && pct <= 100);
    return total * pct / 100;
}

/* Значение пришло извне: неверное штатно, поэтому код ошибки */
static int rate_parse(int raw, int *pct) {
    if (raw < 0 || raw > 100) return -EINVAL;
    *pct = raw;
    return 0;
}

int main(void) {
    int pct;
    if (rate_parse(150, &pct) < 0) puts("bad rate"); /* вывод: bad rate */
    if (rate_parse(25, &pct) == 0) printf("%d\n", percent_of(200, pct)); /* вывод: 50 */
    return 0;
}
```

Условия, известные на этапе компиляции (размер структуры, значение константы), проверяют `static_assert`.

#### Подводные камни

- Побочный эффект в `assert`. Вызов, нужный для работы, при `-DNDEBUG` пропадает вместе с проверкой: результат присвоить переменной, затем проверить её.
- Проверка входа через `assert`. В рабочей сборке такая проверка исчезает, и неверные данные доходят до кода, который на них не рассчитан.
- Переменная, нужная только в `assert`. При `-DNDEBUG` она становится неиспользуемой и вызывает предупреждение; помечай её `[[maybe_unused]]`.

```c
/* Ошибка: запись и проверка внешних данных внутри assert пропадают при NDEBUG */
#include <assert.h>
#include <stdio.h>

void save(FILE *f, const char *s, size_t len_from_file) {
    assert(len_from_file < 4096);
    assert(fputs(s, f) >= 0);
}
```

### Выбери одну схему возврата ошибки и держись её во всём семействе

Читающий код не должен гадать, что означает возвращаемое значение, поэтому для каждого вида функций принята одна схема и она не смешивается. Функция-команда возвращает `int`: 0 успех, отрицательный `-E...` из `<errno.h>` ошибка. Функция-предикат возвращает `bool` и ошибок не сообщает. Функция-создатель возвращает указатель на объект или `nullptr`, а если указатель `err` не `nullptr`, кладёт в него код результата (при ошибке `-E...`, при успехе 0 или ничего, как записано в контракте); параметр необязателен и ставится там, где код нужен вызывающему, а создающая функция с единственной причиной отказа может обойтись без него. Исключений два: функции вида `read`, возвращающие число обработанных байт или `-E...` (например `read` в таблице операций [интерфейсов](06-api-and-modules.md)), и двухфазные функции вида `snprintf`, возвращающие требуемый размер (например `hex_encode` в той же главе). Каждое исключение оформляют как отдельную явно названную схему, и контракт обязан её описывать.

```c
#include <errno.h>
#include <stdbool.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

typedef struct { char *data; size_t len, cap; } buf;

buf *buf_create(size_t cap, int *err) {
    buf *b = calloc(1, sizeof *b);
    if (b) b->data = malloc(cap ? cap : 1);
    if (!b || !b->data) {
        free(b);
        if (err) *err = -ENOMEM;
        return nullptr;
    }
    b->cap = cap;
    return b;
}

int buf_append(buf *b, const char *s, size_t n) {
    if (n > b->cap - b->len) return -ENOSPC;
    memcpy(b->data + b->len, s, n);
    b->len += n;
    return 0;
}

bool buf_empty(const buf *b) { return b->len == 0; }

void buf_destroy(buf *b) {
    if (b) free(b->data);
    free(b);
}

int main(void) {
    int err = 0;
    buf *b = buf_create(4, &err);
    if (!b) return 1;
    printf("%d\n", buf_empty(b)); /* вывод: 1 */
    printf("%d\n", buf_append(b, "abc", 3)); /* вывод: 0 */
    printf("%d\n", buf_append(b, "xyz", 3) == -ENOSPC); /* вывод: 1 */
    buf_destroy(b);
    return 0;
}
```

Когда результат и ошибка возвращаются вместе, по умолчанию результат идёт в out-параметр, а возврат остаётся статусом команды. Небольшое значение, которое проходит через несколько слоёв (срез, число), удобнее вернуть структурой с полем ошибки `typedef struct { long value; int err; } long_result;`: она не требует переменной под результат на каждом уровне.

#### Подводные камни

- Предикат вместо команды. Для `bool buf_flush(...)` вызывающий не отличит «нечего сбрасывать» от «сброс не удался»; если отказ возможен, это команда.
- Инвертированная проверка. У команды `if (buf_append(...))` читается как «добавлено», а означает «ошибка»; ошибку проверяют явно: `< 0` или `!= 0` по контракту.
- Знак кода. Код хранится отрицательным, поэтому для текста берут `strerror(-rc)`, а для присваивания в `errno` меняют знак обратно.
- Значение out-параметра при ошибке. Контракт обязан сказать, что в нём остаётся после ошибки (например «не изменён»); если не сказал, после ошибки его не читают.
- Смесь схем. Функция, которая то возвращает счётчик, то `-E...`, то `nullptr`, заставляет каждого вызывающего помнить исключение; вне двух исключений схемы счётчик возвращай через out-параметр или структуру.

### Не накапливай и не глотай ошибки

Необработанная ошибка превращается в ложный успех или в сбой далеко от причины, поэтому каждая ошибка либо обрабатывается на месте, либо передаётся наверх, а вызывающий проверяет результат после каждого вызова. Функция с необязательным `int *err` последним аргументом обязана установить его при каждой неудаче (иначе вызывающий видит «не получилось» без причины), а при успехе контракт говорит, записывается ли 0 или значение не меняется; допустимо передать `nullptr`, когда причина не нужна.

```c
#include <errno.h>
#include <stddef.h>
#include <stdio.h>
#include <string.h>

static void set_err(int *err, int code) { if (err) *err = code; }

/* port_find: nullptr при ошибке, тогда *err установлен; при успехе *err не меняется */
static const int *port_find(const char *name, int *err) {
    static const struct { const char *name; int port; } tab[] = {{"http", 80}, {"ssh", 22}};
    if (!name) { set_err(err, -EINVAL); return nullptr; }
    for (size_t i = 0; i < sizeof tab / sizeof tab[0]; i++)
        if (strcmp(tab[i].name, name) == 0) return &tab[i].port;
    set_err(err, -ENOENT);
    return nullptr;
}

int main(void) {
    int err = 0;
    const int *p = port_find("ssh", &err);
    printf("%d\n", p ? *p : err); /* вывод: 22 */
    p = port_find("ftp", &err);
    printf("%d\n", p == nullptr && err == -ENOENT); /* вывод: 1 */
    p = port_find(nullptr, nullptr);
    printf("%d\n", p == nullptr); /* вывод: 1 */
    return 0;
}
```

#### Подводные камни

- Результат `fclose`, `close`, `fsync` у записанного файла. Отложенная ошибка записи всплывает именно здесь; проигнорированная, она теряет данные без следа, поэтому результат закрытия проверяют так же, как результат записи.
- Одна переменная `err` на несколько вызовов подряд. Следующий вызов может затереть уже установленную ошибку или оставить её без проверки; проверяй после каждого вызова или возвращай первую ошибку цикла, а остальные логируй.
- Путь отказа без установки `err`. Вызывающий читает старое значение и принимает его за причину; в функции заведи единый `set_err` и вызывай его на каждом `return nullptr`.
- Ошибка поглощена ради «продолжить работу». Допустимо только осознанно и с комментарием, почему отказ безвреден; безмолвный `(void)` без причины считай дефектом.

### Сохраняй errno сразу и проверяй возвраты библиотечных функций

`errno` общая для всех вызовов потока, и любой следующий вызов (в том числе очистка, лог, а по стандарту и успешный) вправе её перезаписать, поэтому значение читают и сохраняют сразу после отказавшего вызова, до любых других действий. Успешный вызов `errno` в 0 не сбрасывает, поэтому по самой `errno` нельзя узнать, был ли отказ: сначала смотрят на возврат функции, и только при признаке отказа читают `errno`.

```c
#define _GNU_SOURCE
#include <errno.h>
#include <fcntl.h>
#include <stdio.h>
#include <unistd.h>

static void release(void) { close(-1); } /* очистка, которая сама отказывает */

static int open_lost(const char *path) {
    int fd = open(path, O_RDONLY);
    if (fd < 0) { release(); return -errno; }
    return fd;
}

static int open_kept(const char *path) {
    int fd = open(path, O_RDONLY);
    if (fd < 0) { int e = errno; release(); return -e; }
    return fd;
}

int main(void) {
    printf("%d\n", open_lost("/no/such") == -ENOENT); /* вывод: 0 */
    printf("%d\n", open_kept("/no/such") == -ENOENT); /* вывод: 1 */
    return 0;
}
```

Возвращаемые значения библиотечных функций проверяют всегда, где отказ возможен: `fopen`, `fclose`, `fwrite`, `snprintf`, `malloc`. Свои функции со статусом помечают `[[nodiscard]]` ([атрибут и контракты API](06-api-and-modules.md)): компилятор предупредит о проигнорированном результате. Автоматически такие места находит проверка clang-tidy `cert-err33-c`. Функции разбора числа (`strtol`) сообщают об отказе через `errno`, которую перед вызовом обнуляют, потому что успешный вызов её не сбрасывает; полный набор проверок описан в практике про разбор чисел ([строки и буферы](05-strings-and-buffers.md)).

`errno` у каждого потока своя, передавать её значение в другой поток как состояние нельзя: передают сохранённый код.

### Добавляй контекст, когда одного кода мало

Код ошибки отвечает программе на вопрос «что делать дальше», но не человеку на вопрос «что именно сломалось»; когда причину нужно показать в логе (файл, позиция, значение), рядом с кодом хранят текст. Текст предназначен для человека, а программа решает по коду: разбирать строку сообщения нельзя. Для этого последним аргументом вместо `int *err` принимают указатель на структуру с кодом и буфером фиксированного размера, который лежит на стеке вызывающего: аллокаций нет, а усечение длинного текста безопасно.

```c
#include <errno.h>
#include <stdarg.h>
#include <stdio.h>

typedef struct { int code; char text[96]; } error;

/* err_set возвращает code, чтобы писать: return err_set(e, -EINVAL, ...); e допустим nullptr */
[[gnu::format(printf, 3, 4)]]
int err_set(error *e, int code, const char *fmt, ...) {
    if (e) {
        va_list ap;
        va_start(ap, fmt);
        vsnprintf(e->text, sizeof e->text, fmt, ap);
        va_end(ap);
        e->code = code;
    }
    return code;
}

static int port_check(int port, error *e) {
    if (port < 1 || port > 65535) return err_set(e, -EINVAL, "port %d out of range", port);
    return 0;
}

int main(void) {
    error e = {};
    printf("%d\n", port_check(70000, &e) == -EINVAL); /* вывод: 1 */
    puts(e.text); /* вывод: port 70000 out of range */
    return 0;
}
```

Атрибут `format` (расширение GCC/Clang) заставляет компилятор проверять строку формата при вызове `err_set`, как у `printf`. В одном семействе функций выбирают одно: либо `int *err`, либо `error *`.

Собственные коды ошибок модуля, не совпадающие с `errno`, перечисляют вместе с их текстами из одного списка, чтобы они не расходились: приём X-macro ([контейнеры и обобщённый код](09-containers-and-generics.md)) генерирует и `enum`, и таблицу строк. Значения начинают выше диапазона `errno`, а для кодов из `errno` берут `strerror`.

```c
#include <errno.h>
#include <stdio.h>
#include <string.h>

#define ERR_LIST(X) \
    X(ERR_SYNTAX, "syntax error") \
    X(ERR_EOF, "unexpected end of input") \
    X(ERR_DEPTH, "nesting too deep")

enum {
    ERR_BASE = 1000,
#define X(name, text) name,
    ERR_LIST(X)
#undef X
    ERR_END
};

/* code: код errno или собственный, знак любой: -ENOENT, -ERR_EOF и ERR_EOF дают один текст */
const char *err_text(int code) {
    static const char *const texts[] = {
#define X(name, text) [name - ERR_BASE - 1] = text,
        ERR_LIST(X)
#undef X
    };
    if (code < 0) code = -code;
    if (code < ERR_BASE) return strerror(code);
    if (code == ERR_BASE || code >= ERR_END) return "unknown error";
    return texts[code - ERR_BASE - 1];
}

int main(void) {
    puts(err_text(-ERR_EOF)); /* вывод: unexpected end of input */
    puts(err_text(-ENOENT)); /* вывод: No such file or directory */
    return 0;
}
```

#### Подводные камни

- Разбор текста. Условие вида `strstr(e.text, "timeout")` ломается при правке формулировки; ветвление идёт по коду, а для новой ситуации заводят новый код.
- Текст на горячем пути. Заполнять `error` при штатном отказе (`EAGAIN`) значит платить форматированием на каждый вызов; для таких случаев хватает кода без структуры.
- Забытая установка при ошибке. Структура остаётся нулевой, и в лог попадает пустая строка; `err_set` вызывают на каждом пути отказа, и сразу в `return`.

## Очистка

### Освобождай ресурсы на единой точке выхода через goto

Функция, держащая несколько ресурсов, при выходе из середины легко пропускает освобождение, поэтому все выходы ведут на одну точку, где ресурсы освобождаются разом, а метки называют по действию (`out_free_buffer`), а не по номеру (`err1`). Все переменные-ресурсы объявляют в начале и инициализируют `nullptr` (для дескрипторов `-1`): тогда на метке освобождение безусловное и работает на любом пути, а `free(nullptr)` безопасен.

```c
#include <errno.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

/* longest_line: самая длинная строка; владение результатом у вызывающего */
static int longest_line(FILE *f, char **out) {
    int ret = 0;
    char *line = nullptr, *best = nullptr;
    size_t max = 0;

    line = malloc(256);
    best = malloc(256);
    if (!line || !best) { ret = -ENOMEM; goto out_free_buffers; }
    best[0] = '\0';
    while (fgets(line, 256, f)) {
        size_t n = strlen(line);
        if (n > max) { max = n; memcpy(best, line, n + 1); }
    }
    if (ferror(f)) { ret = -EIO; goto out_free_buffers; }
    *out = best;
    best = nullptr; /* владение передано, free на выходе ничего не делает */
out_free_buffers:
    free(best);
    free(line);
    return ret;
}

int main(void) {
    FILE *f = tmpfile();
    if (!f) return 1;
    if (fputs("ab\nlonger line\nxyz\n", f) < 0) return 1;
    rewind(f);
    char *s = nullptr;
    if (longest_line(f, &s) == 0) printf("%s", s); /* вывод: longer line */
    free(s);
    return fclose(f) == 0 ? 0 : 1;
}
```

Возврат из середины функции, минуя метку, оставляет утечку, а успешный путь, который проваливается в метки освобождения, освободит то, что должен получить вызывающий; поэтому передаваемый ресурс обнуляют перед выходом, как `best` выше.

#### Подводные камни

- Прыжок через определение. `goto` вперёд мимо `int v = 7;` оставляет `v` неинициализированной, и чтение даёт мусор; объявления ресурсов поднимай выше первого `goto`.
- Определение с очисткой. Переменную с `__attribute__((cleanup))` `goto` перепрыгивать не должен: Clang отказывается компилировать такой переход, а GCC компилирует и на выходе вызывает очистку над неинициализированным значением.
- Объявление после `case`. Переменная видна во всём `switch`, и переход на другую метку минует её инициализацию; тело метки с объявлением заключай в блок `{ ... }`.
- Освобождающая функция без терпимости к пустому значению. `free(nullptr)` допустим, а `fclose(nullptr)` нет, поэтому `if (f) fclose(f);`; для дескрипторов `-1` до открытия и проверка перед `close`.
- Потеря ошибки закрытия. Для записанного файла результат `fclose` в точке выхода присваивают `ret`, если до этого ошибки не было.

### Откатывай частичную инициализацию лестницей меток

Функция-создатель, у которой отказывает третий шаг, обязана освободить результат первых двух, и только их: лестница меток освобождает ресурсы в порядке, обратном получению, а прыжок на метку означает «всё, что получено до этого места, освободи». Успешный путь возвращает результат до первой метки, не заходя на лестницу.

```c
#include <errno.h>
#include <stdlib.h>

typedef struct { char *rbuf, *wbuf; } conn;

static int handshake(int version) { return version == 1 ? 0 : -EPROTO; }

conn *conn_create(size_t cap, int version, int *err) {
    int ret;
    conn *c = malloc(sizeof *c);
    if (!c) { ret = -ENOMEM; goto err_report; }
    c->rbuf = malloc(cap);
    if (!c->rbuf) { ret = -ENOMEM; goto err_free_conn; }
    c->wbuf = malloc(cap);
    if (!c->wbuf) { ret = -ENOMEM; goto err_free_rbuf; }
    ret = handshake(version);
    if (ret < 0) goto err_free_wbuf;
    return c;

err_free_wbuf:
    free(c->wbuf);
err_free_rbuf:
    free(c->rbuf);
err_free_conn:
    free(c);
err_report:
    if (err) *err = ret;
    return nullptr;
}

void conn_destroy(conn *c) {
    if (!c) return;
    free(c->wbuf);
    free(c->rbuf);
    free(c);
}

int main(void) {
    int err = 0;
    conn *c = conn_create(64, 2, &err); /* рукопожатие отказывает: лестница освобождает всё */
    conn_destroy(c);
    c = conn_create(64, 1, &err);
    conn_destroy(c);
    return err == -EPROTO ? 0 : 1;
}
```

LeakSanitizer находит пропущенный шаг лестницы только на исполненном пути, а отказный путь в обычном прогоне не выполняется; поэтому каждый путь выхода проходят имитацией отказов ([тесты и инжекция отказов](07-testing-and-debugging.md)). Соблазн заменить лестницу одной меткой опасен:

```c
/* Ошибка: единая метка читает c->rbuf, а c может быть nullptr */
#include <stdlib.h>

typedef struct { char *rbuf; } conn;

conn *conn_create_bad(size_t cap) {
    conn *c = malloc(sizeof *c);
    if (!c) goto fail;
    c->rbuf = malloc(cap);
    if (!c->rbuf) goto fail;
    return c;
fail:
    free(c->rbuf);
    free(c);
    return nullptr;
}
```

Опасен первый переход: при `c == nullptr` чтение `c->rbuf` недопустимо. Второй переход безопасен только потому, что `rbuf` получил `nullptr` от `malloc`; при третьем ресурсе, выделяемом после `rbuf`, тот же код освободил бы ещё не заданное поле. Одна метка работает, только если объект создан `calloc` (поля нулевые), а очистка пропускает `nullptr`: `if (c) free(c->rbuf);`. Это нулевое состояние, пригодное к уничтожению ([парная функция уничтожения](03-memory-ownership.md)).

#### Подводные камни

- Порядок меток. Освобождение идёт обратно получению: метка нижнего ресурса стоит выше метки того, что получено раньше, иначе освобождается ещё не выделенное.
- Новый шаг в середине. Добавленный ресурс требует новой метки и правки переходов после него; пропущенная правка даёт утечку или двойное освобождение на одном пути.
- Освобождение после передачи. Ресурс, уже отданный владельцу (записанный в долгоживущую структуру), лестница освобождать не должна: иначе двойное освобождение; передачу делают последним шагом, после которого отказов нет.
- Много ресурсов. Лестница из пяти и более меток тяжело сопровождается; тогда делят функцию на шаги или применяют автоматическую очистку (см. раздел `Коротко`).

## Выход из программы

### Завершай программу через return из main, а очистку пропускай только осознанно

Штатный путь это `return` из `main` или `exit`: они вызывают обработчики `atexit` и сбрасывают stdio, поэтому вывод не теряется. Пропуск очистки нужен только для аварийного завершения.

| Вызов | atexit | Сброс stdio | Статус оболочки |
| --- | --- | --- | --- |
| `return` из `main`, `exit` | да, в обратном порядке | да | переданный код |
| `_Exit` | нет | нет | переданный код |
| `quick_exit` | только `at_quick_exit` | нет | переданный код |
| `abort` | нет | нет | 134 (сигнал `SIGABRT`) |

Типичное применение `_Exit` это дочерний процесс после `fork`: копия буфера stdio родителя, сброшенная `exit`, дублирует вывод.

```c
#define _GNU_SOURCE
#include <stdio.h>
#include <stdlib.h>
#include <sys/wait.h>
#include <unistd.h>

int main(void) {
    printf("parent buffer\n"); /* вывод: parent buffer */
    pid_t p = fork();
    if (p == 0) _Exit(0); /* exit(0) сбросил бы копию буфера второй раз */
    int st;
    waitpid(p, &st, 0);
    return 0;
}
```

Решение завершить процесс принимает `main`, а не библиотечная функция: библиотека возвращает ошибку, потому что `exit` изнутри пропускает очистку всех вызывающих. Политика нехватки памяти (завершать сразу или возвращать `-ENOMEM`) выбирается один раз на программу ([политика нехватки памяти](03-memory-ownership.md)).

#### Подводные камни

- Выход при работающих потоках. `return` из `main` и `exit` завершают весь процесс вместе с другими потоками, не дожидаясь их; потоки останавливают и присоединяют до выхода ([потоки](10-concurrency.md)).
- Обработчик `atexit`. Он вызывается без аргументов и обязан вернуться нормально; повторный `exit` и `longjmp` из него недопустимы.
- Код завершения. Оболочка видит только младшие 8 бит значения; используй `EXIT_SUCCESS` и `EXIT_FAILURE`.

## Коротко

### Автоматическая очистка через cleanup

Расширение GCC/Clang `__attribute__((cleanup(f)))` вызывает `f` с указателем на переменную при выходе из области видимости, на любом пути, включая `return`, в порядке, обратном объявлению. Переменную инициализируют сразу в объявлении, а `f` терпит `nullptr`. В одной функции не смешивают `goto` и автоочистку: переход через такое объявление Clang запрещает, а GCC допускает и очищает неинициализированное. Передачу владения оформляют приёмом «steal»: указатель отдаётся наружу и обнуляется (макрос на `typeof` и выражении в скобках, расширение GCC/Clang).

```c
#include <stdlib.h>

#define STEAL(p) ({ typeof(p) steal_tmp_ = (p); (p) = nullptr; steal_tmp_; })

static void free_str(char **p) { free(*p); }

char *build(void) {
    char *res __attribute__((cleanup(free_str))) = malloc(16);
    if (!res) return nullptr;
    return STEAL(res); /* res обнулён: очистка ничего не освободит */
}
```

### setjmp и longjmp

`setjmp` запоминает точку, `longjmp` возвращает в неё управление из любой глубины вызовов, пропуская всё между ними, включая освобождение ресурсов. Правила: `setjmp` вызывают только в простом сравнении (`if (setjmp(env) == 0)`), не в выражении и не с сохранением результата; локальные переменные, изменённые после `setjmp` и читаемые после `longjmp`, объявляют `volatile`; `longjmp` в функцию, которая уже вернулась, неопределённое поведение. Оправдан он там, где ошибка из глубокой рекурсии (разбор вложенных данных) должна выбросить всю работу целиком в одном модуле, а наружу выходит обычный код ошибки; во всех остальных случаях хватает возвратов.

```c
#include <setjmp.h>
#include <stdio.h>

static jmp_buf on_error;

static void parse(const char *s) { /* конец строки это ошибка */
    if (*s == '\0') longjmp(on_error, 1);
    if (*s != ')') parse(s + 1);
}

int main(void) {
    if (setjmp(on_error) != 0) { puts("recovered"); return 0; } /* вывод: recovered */
    parse("((x");
    return 1;
}
```

### Предусловия и рекурсия

В рекурсивной функции условие остановки стоит первым, проверки входа делают один раз во внешней обёртке, а глубину, зависящую от внешних данных, ограничивают и при превышении возвращают `-E2BIG`: исчерпание стека необратимо, а проверить его заранее нельзя.

## Что ещё стоит знать

Автоматическую очистку без расширений даёт `defer` из технического стандарта: в Clang 22 он включается флагом `-fdefer-ts`, на базовой линии книги его нет. `abort` может оставить дамп памяти (core dump), который читает отладчик ([отладка](08-debugging.md)).

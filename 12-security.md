# Безопасность

## Секреты

### Бери случайные числа для секретов у операционной системы

Результат `rand` и `random` вычисляется детерминированной формулой по небольшому начальному значению, поэтому по нескольким выходам атакующий восстанавливает состояние и предсказывает остальные; для ключей, токенов сессий и солей годится только системный источник. Функция `getentropy` (нестандартная: glibc 2.25 и новее, BSD) заполняет буфер случайными байтами, но принимает не больше 256 байт за вызов; при большей длине возвращает ошибку `EIO`, поэтому длинный буфер заполняют кусками. В glibc она объявлена в `<sys/random.h>` (макросы не нужны) и в `<unistd.h>` (там нужен `_DEFAULT_SOURCE`). Результат проверяют всегда: молчаливый возврат к `rand` или `time` при ошибке превращает секрет в предсказуемое значение.

```c
#include <errno.h>
#include <stdio.h>
#include <string.h>
#include <sys/random.h>

/* sec_random - заполняет buf криптостойкими случайными байтами.
 * Возврат: 0 или -errno; при ошибке содержимое buf не определено и использовать его нельзя. */
int sec_random(void *buf, size_t n) {
    unsigned char *p = buf;
    while (n > 0) {
        size_t k = n < 256 ? n : 256;
        if (getentropy(p, k) != 0) return -errno;
        p += k;
        n -= k;
    }
    return 0;
}

int main(void) {
    unsigned char a[600], b[600];
    if (sec_random(a, sizeof a) != 0 || sec_random(b, sizeof b) != 0) return 1;
    char token[33];
    for (int i = 0; i < 16; i++) snprintf(token + 2 * i, 3, "%02x", a[i]);
    printf("%zu\n", strlen(token)); /* вывод: 32 */
    printf("%d\n", memcmp(a, b, sizeof a) != 0); /* вывод: 1 */
    return 0;
}
```

Функция `getrandom` (`<sys/random.h>`, Linux) даёт то же с флагами и может вернуть меньше байт, чем запрошено, поэтому её результат сверяют с длиной; `getentropy` проще, и обычно её достаточно.

#### Подводные камни

- `srand(time(nullptr))` и любые `rand()`, `random()`, `drand48()` для токенов, паролей, ключей, идентификаторов сессий. Сид от времени атакующий угадывает перебором ближайших секунд, а `getentropy` сид не требует: она сама возвращает случайные байты. Значения предсказуемы; такие функции оставляют для симуляций и тестовых данных.
- Выбор числа в диапазоне как `x % n`. Остатки распределены неравномерно, если `n` не делит диапазон `x`; отбрасывай значения выше наибольшего кратного `n` и бери новое.
- Длина больше 256. `getentropy` вернёт `-1` с `EIO`, а не заполнит часть буфера; заполняй кусками, как в примере.
- Вызов на самой ранней стадии загрузки системы. До инициализации системного источника вызов может блокироваться; ошибку не обходят запасным генератором, а ждут или завершают запуск.
- Секрет, оставшийся в памяти после использования. Затирай его по правилу ниже.

### Затирай секреты функцией, которую оптимизатор не удалит

Запись в память, которую после этого никто не читает, не имеет наблюдаемого эффекта, поэтому оптимизатор вправе её удалить: `memset` перед `free` или перед выходом из функции исчезает, и ключ остаётся в освобождённом блоке или на стеке. Проверь сам: `cc -std=c23 -O2 -S` для функции ниже. Компиляторы оставляют в ассемблере только переход на `free`, а для локального массива не оставляют вообще ничего.

```c
/* Ошибка: запись нулей перед free не читается дальше, оптимизатор её удаляет */
#include <stdlib.h>
#include <string.h>

void key_free(char *key, size_t n) {
    memset(key, 0, n);
    free(key);
}
```

```text
key_free с memset (все три компилятора, -O2):    jmp free@PLT
то же с explicit_bzero перед free:               вызов explicit_bzero и затем jmp free@PLT
```

Функция `explicit_bzero` (нестандартная: glibc 2.25 и новее, BSD; `<string.h>`, под `-std=c23` нужен `_DEFAULT_SOURCE`) записывает нули так, что компилятор не вправе её удалить. Стандартный аналог `memset_explicit` появился в C23, но в glibc 2.39 его нет, поэтому в книге используется `explicit_bzero`. Затирание встраивают в `clear` секретного объекта ([жизненный цикл `init`/`clear`](03-memory-ownership.md)).

```c
#define _DEFAULT_SOURCE
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

typedef struct { unsigned char key[32]; size_t len; } secret;

void secret_clear(secret *s) { explicit_bzero(s, sizeof *s); }

void secret_destroy(secret *s) {
    if (!s) return;
    secret_clear(s);
    free(s);
}

int main(void) {
    secret *s = calloc(1, sizeof *s);
    if (!s) abort();
    memset(s->key, 'k', sizeof s->key);
    s->len = sizeof s->key;
    secret_clear(s);
    unsigned sum = 0;
    for (size_t i = 0; i < sizeof s->key; i++) sum += s->key[i];
    printf("%u %zu\n", sum, s->len); /* вывод: 0 0 */
    secret_destroy(s);
    return 0;
}
```

#### Подводные камни

- Копии секрета. `realloc` переносит блок и оставляет старый нетронутым, `strdup` и буферы ввода-вывода (`fgets` из `stdin`) хранят свои копии, значение остаётся в регистрах и временных переменных на стеке; держи секрет в одном буфере фиксированного размера и затирай каждую копию, до которой можно добраться.
- Секрет в журнале, сообщении об ошибке или командной строке процесса. Затирание памяти этого не исправит; такие значения не выводят вовсе, а в журнале оставляют идентификатор или длину.
- Секрет в дампе памяти. Ядро записывает его в файл при аварии; отключают дамп для региона (`madvise` с `MADV_DONTDUMP`) или для процесса (`setrlimit(RLIMIT_CORE, ...)`).
- Секрет в области подкачки. Страницы с ключом закрепляют `mlock`: лимит `RLIMIT_MEMLOCK` небольшой, поэтому закрепляют только сами секреты.
- Затирание после `free`. Блок уже может принадлежать другому коду; затирай до освобождения, как в `secret_destroy`.
- Секрет зашит в исходный текст или в образ (ключ в строковом литерале, пароль в репозитории). Он живёт в каждом бинарнике и в истории; секреты читают на старте из окружения, файла с жёсткими правами доступа или хранилища секретов.

### Сравнивай секреты за постоянное время

`memcmp` и `strcmp` выходят на первом различии, и время ответа показывает, сколько первых байт токена или подписи угадано, поэтому секреты сравнивают циклом, который всегда проходит весь буфер и накапливает различия. Побитовое ИЛИ результатов XOR по всем байтам равно нулю тогда и только тогда, когда буферы равны; ветвление выполняется один раз, после цикла.

```c
#include <stdbool.h>
#include <stddef.h>
#include <stdio.h>

/* sec_equal - равны ли n байт; время зависит только от n.
 * a, b: не nullptr, заимствуются, ровно n байт каждый. */
bool sec_equal(const void *a, const void *b, size_t n) {
    const unsigned char *x = a, *y = b;
    unsigned char diff = 0;
    for (size_t i = 0; i < n; i++) diff = (unsigned char)(diff | (x[i] ^ y[i]));
    return diff == 0;
}

int main(void) {
    char t[] = "s3cr3t-token-0001";
    char early[] = "x3cr3t-token-0001", late[] = "s3cr3t-token-0002";
    printf("%d\n", sec_equal(t, t, sizeof t)); /* вывод: 1 */
    printf("%d\n", sec_equal(t, early, sizeof t)); /* вывод: 0 */
    printf("%d\n", sec_equal(t, late, sizeof t)); /* вывод: 0 */
    return 0;
}
```

Оптимизатор в принципе вправе добавить ранний выход, но на `-O2` и `-O3` компиляторы этого не делают: в ассемблере остаются переходы только по счётчику цикла и по `n`, а векторизованный вариант накапливает различия так же. Свою реализацию проверяй просмотром ассемблера после смены компилятора или флагов; готовая функция из криптобиблиотеки (`CRYPTO_memcmp` в OpenSSL, `sodium_memcmp` в libsodium) предпочтительнее собственной, потому что за этим следит её разработчик.

#### Подводные камни

- Сравнение с разной длиной. Длину сравнивают открыто до цикла; сама длина при этом раскрывается, поэтому сравнивай значения фиксированной длины (подпись, хеш) и сравнивай хеш или код аутентификации, а не пароль.
- `strcmp` и `memcmp` для токенов, подписей, кодов аутентификации. Выход на первом различии даёт канал по времени, измеримый даже по сети при достаточном числе запросов.
- Результат сравнения, возвращённый как число различий или разность байт. Вызывающий код ветвится по нему так же рано; возвращай `bool`.
- Своя реализация на других размерах. Другой компилятор или уровень оптимизации может вернуть ветвление по данным; проверяй ассемблер или используй библиотеку.

## Граница доверия

### Проверяй всё, что приходит извне, до использования

Данные из сети, файлов, аргументов, окружения и от других процессов считаются недоверенными, пока не проверены на границе модуля: проверки внутри уже слишком поздно, потому что длина или индекс к тому времени использованы в арифметике и адресации. Правило общее, а подробности каждого случая разобраны в профильных главах.

| Источник | Что проверить | Где разобрано |
| --- | --- | --- |
| Длина, счётчик, смещение из пакета или файла | Диапазон и согласованность с размером буфера до арифметики; размеры считать в `size_t` через `ckd_mul` и `ckd_add` | [целые типы](02-types-and-ub.md), [выделение памяти](03-memory-ownership.md) |
| Строка из ввода | Явная длина, срез вместо NUL-строки, усечение при форматировании | [строки и буферы](05-strings-and-buffers.md) |
| Форматная строка | Только литерал; ввод передаётся как аргумент `%s`; флаг `-Wformat=2` (включает `-Wformat-security`, а вместе с `-Werror` предупреждение становится ошибкой) | [строки и буферы](05-strings-and-buffers.md), [флаги](01-toolchain.md) |
| Имя файла и путь | Проверка и открытие одной операцией, работа через дескриптор, а не повторное обращение по имени | [системный уровень](11-system-io.md) |
| Запуск программ | `execve` с массивом аргументов и абсолютным путём вместо `system` и `popen` со склеенной строкой | [системный уровень](11-system-io.md) |
| Размеры полей бинарного протокола | Каждое поле проверено по оставшейся длине сообщения до чтения | [системный уровень](11-system-io.md) |
| Окружение и аргументы | Копия значения, проверка длины и содержимого; см. ниже | эта глава |

Окружение процесса в обычной программе подконтрольно тому, кто её запускает, поэтому `getenv` возвращает недоверенный ввод. Возвращённый указатель ведёт внутрь самого окружения и недействителен после `setenv`, `putenv`, `unsetenv` и `clearenv`, поэтому значение копируют сразу. Расширение GNU `secure_getenv` возвращает `nullptr`, если процесс запущен в режиме повышенных прав (бит setuid или setgid, файловые привилегии): так библиотека не доверяет окружению процесса, у которого другие права, чем у запустившего.

```c
#define _GNU_SOURCE
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

/* env_dup - копия значения переменной окружения.
 * Возврат: строка, которую освобождает вызывающий, или nullptr, если переменной нет,
 * значение пустое или длиннее max. */
char *env_dup(const char *name, size_t max) {
    const char *v = secure_getenv(name);
    if (!v || !*v || strnlen(v, max + 1) > max) return nullptr;
    return strdup(v);
}

int main(void) {
    setenv("APP_DIR", "/srv/app", 1);
    char *dir = env_dup("APP_DIR", 64);
    if (!dir) return 1;
    setenv("APP_DIR", "/tmp", 1); /* копия dir от изменения окружения не зависит */
    printf("%s\n", dir); /* вывод: /srv/app */
    free(dir);
    setenv("APP_DIR", "/a/very/long/path/that/exceeds/the/allowed/maximum/length/of/the/value", 1);
    printf("%d\n", env_dup("APP_DIR", 32) == nullptr); /* вывод: 1 */
    return 0;
}
```

#### Подводные камни

- `PATH`. Запуск программы по имени из недоверенного окружения исполняет подставленный файл; запускай по абсолютному пути и передавай дочернему процессу явный список окружения, а не унаследованный.
- `LD_PRELOAD` и `LD_LIBRARY_PATH`. Они подменяют библиотеки процесса; в режиме повышенных прав загрузчик их отбрасывает, но обычный процесс получает их от запустившего, поэтому не пробрасывай собственное окружение процессам с другим уровнем доверия.
- Значение из окружения как путь, команда или формат. Каждое такое применение проходит ту же проверку, что и данные из сети.
- Хранение указателя из `getenv`. Копия сразу после чтения; указатель ломается при любом изменении окружения, в том числе из другого потока.
- Проверка после использования. Длина и диапазон проверяются до первого индексирования и умножения; проверка, стоящая после, ничего не защищает.

## Что ещё стоит знать

Сброс привилегий делают в порядке `setgroups`, `setgid`, `setuid` и затем проверяют, что возврат невозможен (`setuid(0)` должен завершиться ошибкой); привилегии оставляют только на время действия, которому они нужны. Привязку массива к полю длины даёт атрибут `counted_by`, а проверки границ по таким аннотациям на уровне компилятора обещает `-fbounds-safety` (в Clang 19 и 20 флаг не принимается; [гибкий массив](03-memory-ownership.md), [флаги и санитайзеры](01-toolchain.md)). Криптографию (шифры, подписи, хеши, сравнение, генерацию ключей) берут из готовой библиотеки, а собственную реализацию не пишут. При записи структуры в файл или сокет байты дополнения (padding) могут нести содержимое кучи или стека: обнуляй структуру целиком перед заполнением или сериализуй поля по одному.
